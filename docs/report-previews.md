## Refresh saved outputs

```bash
.venv/bin/python code/scripts/render_reports.py
# One report only:
.venv/bin/python code/scripts/render_reports.py --only obrasgov_preprocessing
.venv/bin/python code/scripts/verify_reports.py
```

Each script runs in a fresh process against saved local artifacts. Result review copies, exact-byte PNGs and a completed checksum manifest are written under `outputs/reports/`. Review the new outputs and copy approved values/figures into the maintained Markdown. Report edits are never overwritten. Interactive maps stay under `outputs/maps/` or on the website; missing inputs remain explicit notices. Source data is not acquired or recomputed by refreshing a report.

## Script audit

The Python renderer preserves rich-output order (standard output is recorded separately), captures table/image values, limits artifact sizes and rejects embedded scripts/iframes. It publishes a review file atomically only after successful execution/validation. Failures preserve the previous review file; earlier successful files may be updated before a later report fails, while the prior completed manifest remains unchanged. Check fingerprints before adopting results. Rerun interrupted captures; concurrent refreshes are unsupported.

Maintained narratives are protected by an output-path check and separate storage. Direct Python scripts contain saved-output display logic, while the stage CLI remains responsible for analysis. The obsolete QMD generator and editor configuration were removed after archival so routine work cannot recreate duplicate reports. Numerical methods and the live website were not changed.
