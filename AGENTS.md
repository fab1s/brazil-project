# Agent working instructions

Status: current · Last updated: 2026-10-27 · Version: 1.0 · Scope: Four final research datasets and the separate map website

Read [README.md](README.md), the affected dataset's `build.ipynb` and `processing.py`, [project.toml](project.toml), and [NOTICE.md](NOTICE.md) before changing a dataset. The [archived full project](https://github.com/fab1s/brazil-project/tree/archive/full-project-2026-10-27) holds earlier reports, detailed audits, original scripts, and documents when historical context is needed.

- Keep the main branch focused on the four `datasets/` folders, their shared processing code in `code/`, and browser source in `website/`. Put the method and processing explanation in the relevant notebook; update the root README only for navigation, setup, output contracts or recovery.
- Preserve original `data/` inputs and the OneDrive source. Write derived intermediates under `data/intermediate/`, generated checks under `outputs/`, and the four handoff GeoPackages as local `datasets/*/final.gpkg`. Never commit full datasets, caches, generated outputs, session files, credentials, or provider data without publication rights.
- Keep existing tract identifiers, year definitions, CRS, denominators, missingness, income weighting, geometry, and exclusions unless the researcher explicitly authorizes a method change. Census analytical areas have one merged 2022 feature per `common_id`, backed by a complete versioned harmonisation bundle. Preserve unmatched tracts separately.
- Obrasgov screening does not correct coordinates. Polygons are omitted from its map derivative; all 2,346 components entirely outside the reported primary state are excluded from that derivative and retained in its audit. Do not sum project investments over geometry components.
- Acquisition and website publication are explicit. Running a dataset notebook uses local inputs and must not download data or change the published site. The notebooks present the method and small saved results; reusable calculations belong in `code/`.
- After changing a dataset, update its notebook explanation, source links, output counts/checksums, and any applicable README or attribution. Document the exact inputs, processing order, output layers, limitations, and verification in that notebook. Avoid duplicate narrative files and edit histories.
- Run focused checks. Compare identifiers, row counts, CRS, geometry, values and missingness where the method can change. A passing software test does not establish national scientific parity. Check recovery after partial writes and verify that earlier final files stay intact on failure.
- Protect unrelated user work. Preserve the complete earlier content on the archive branch; move any local historical documents to `.local-archive/` rather than discarding their contents. Avoid adding empty placeholder files.
